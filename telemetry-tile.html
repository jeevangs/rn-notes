Live Telemetry Tile — Composite Build

Progressive, block-by-block: a dashboard of tiles, each showing one source's live battery % and speed, updating over a WebSocket at ~5Hz without re-rendering the whole grid.

Architecture & build order

A Zustand store byId: Record<string, Telemetry> is the live source of truth. Frames are coalesced in a non-reactive buffer and flushed on an interval, so React renders at ~5Hz instead of per-frame. Each tile subscribes to only its own id, so only the changed tile re-renders.

WebSocket frames  (~30–60/sec, bursty)
        │
        ▼
buffer (ref / module object)        ← NON-reactive: writes do NOT re-render
        │   setInterval ~200ms (5Hz)
        ▼   flush + clear
Zustand store   byId[id] = Telemetry  ← single source of truth (ts-guarded merge)
        │
        ▼   per-id selector: useStore(s => s.byId[id])
Tile (memo)     one tile re-renders    ← only the changed id, not the grid
        ▲
        │
REST baseline (useQuery) seeds byId on mount; WS deltas patch from there

Build order — keep something runnable at every step: render → store → ingest → per-tile select → baseline → harden. Start with the store + a fake emitter so tiles paint, then layer the real socket and guards.

ATypes / data model

vehicleId keys the store map and routes each frame to its tile. ts drives the stale-frame guard. Battery is a percent; speed is a scalar — both are the only fields a tile renders.

import { z } from 'zod';

const TelemetrySchema = z.object({
  vehicleId: z.string(),             // map key → ROUTES the frame to its tile
  battery: z.number(),               // percent 0–100
  speed: z.number(),                 // scalar
  ts: z.number(),                    // epoch ms → STALE-FRAME guard
});
const TelemetryListSchema = z.array(TelemetrySchema);

type Telemetry = z.infer<typeof TelemetrySchema>;

BStore — the spine

A Zustand create with byId and one applyPatch action. The action is ts-guarded: a frame that is older than what is already stored is dropped, so a late/out-of-order delivery never overwrites a newer value. Writing per-id (not replacing the whole map) is what lets a per-id selector stay narrow.

import { create } from 'zustand';

type TelemetryState = {
  byId: Record<string, Telemetry>;
  applyPatch: (patch: Telemetry) => void;
  applyMany: (patches: Telemetry[]) => void;   // used by the flush (one render for the batch)
};

export const useStore = create<TelemetryState>((set, get) => ({
  byId: {},

  applyPatch: (patch) => {
    const prev = get().byId[patch.vehicleId];
    if (prev && prev.ts >= patch.ts) return;     // ts-guard: drop stale / out-of-order
    set((s) => ({ byId: { ...s.byId, [patch.vehicleId]: patch } }));
  },

  applyMany: (patches) => set((s) => {
    const next = { ...s.byId };
    for (const p of patches) {
      const prev = next[p.vehicleId];
      if (prev && prev.ts >= p.ts) continue;      // same guard, applied per id in the batch
      next[p.vehicleId] = p;
    }
    return { byId: next };                       // one set() → one render pass for the whole flush
  }),
}));

CIngest — coalesce + flush

The hook opens the socket and writes every incoming frame into a buffer ref (not state — writes here do not re-render). A setInterval flushes the buffer into the store every FLUSH_MS and clears it. Last frame per id wins inside the buffer, so a burst collapses to one patch per id per flush.

function useTelemetryIngest() {
  const bufferRef = useRef<Record<string, Telemetry>>({});

  // WRITER: every frame coalesces into the buffer (non-reactive — no render)
  useTelemetrySocket((frame) => {
    const prev = bufferRef.current[frame.vehicleId];
    if (prev && prev.ts >= frame.ts) return;       // keep newest within the buffer window
    bufferRef.current[frame.vehicleId] = frame;
  });

  // FLUSH: drain the buffer into the store at 5Hz, then clear
  useEffect(() => {
    const id = setInterval(() => {
      const batch = Object.values(bufferRef.current);
      if (batch.length === 0) return;
      bufferRef.current = {};                       // clear before applying (avoid losing arrivals mid-flush)
      useStore.getState().applyMany(batch);
    }, FLUSH_MS);
    return () => clearInterval(id);
  }, []);
}

Why the buffer is a ref, not state: 30–60 frames/sec into useState would queue 30–60 renders/sec. The ref absorbs the burst silently; only the interval touches the store, capping renders at ~5/sec.

DTile — narrow per-id subscription

The tile reads only its own id from the store. When that id's value changes, only this tile re-renders — the other tiles' selectors return the same reference and skip. Wrapping in memo stops a parent render from cascading.

const Tile = memo(function Tile({ id }: { id: string }) {
  const t = useStore((s) => s.byId[id]);          // ◀ subscribe to ONE id only

  if (!t) return <View style={styles.tile}><Text style={styles.dim}>{id} — waiting…</Text></View>;

  return (
    <View style={styles.tile}>
      <Text style={styles.tileId}>{id}</Text>
      <Text style={styles.metric}>{Math.round(t.battery)}%</Text>
      <Text style={styles.sub}>{Math.round(t.speed)} mph</Text>
    </View>
  );
});

Wrong: const all = useStore((s) => s.byId) in the parent and pass all[id] down — every tile re-renders on any id's change, because the whole-map reference changes each patch. Right: each tile selects s.byId[id] itself, so a patch to one id wakes one tile.

// label-bad — whole-collection selector: one frame → N tiles re-render
const all = useStore((s) => s.byId);              // new object ref every patch
return ids.map((id) => <Tile data={all[id]} />);   // all N re-render

// label-good — per-id selector inside each Tile: one frame → 1 tile re-renders
const t = useStore((s) => s.byId[id]);            // unchanged ids return same ref → skip

EBaseline + reconnect

A REST useQuery seeds initial values into the store on mount, so tiles show real numbers before the first socket frame. WS deltas patch from there. Reconnect / backoff is owned by useWebSocket — the ingest layer never sees a disconnect.

function useBaseline() {
  return useQuery({
    queryKey: ['telemetry-baseline'],
    queryFn: getBaseline,
    staleTime: Infinity,                          // seed once; live deltas keep it fresh after
    onSuccess: (rows) => useStore.getState().applyMany(rows),  // ts-guarded → live frames already won't be clobbered
  });
}

Because applyMany is ts-guarded, a late baseline response can never overwrite a newer live frame that already arrived — the seed and the stream share one merge rule.

mechanismuseWebSocket (generic)

A reusable transport primitive — stable-ref handler so it reconnects only on [url], with jittered backoff. The telemetry layer wraps this; it knows nothing about telemetry.

type WsStatus = 'idle' | 'connecting' | 'open' | 'closed';

function useWebSocket<T>(url: string, onMessage: (msg: T) => void) {
  const [status, setStatus] = useState<WsStatus>('idle');
  const wsRef = useRef<WebSocket | null>(null);
  const attemptsRef = useRef(0);
  const isMountedRef = useRef(true);
  const onMessageRef = useRef(onMessage);
  onMessageRef.current = onMessage;                 // latest handler, every render — no reconnect

  useEffect(() => {
    isMountedRef.current = true;

    const connect = () => {
      if (!isMountedRef.current) return;
      setStatus('connecting');
      const ws = new WebSocket(url);
      wsRef.current = ws;

      ws.onopen = () => { attemptsRef.current = 0; setStatus('open'); };
      ws.onmessage = (e) => { try { onMessageRef.current(JSON.parse(e.data) as T); } catch {} };
      ws.onerror = () => ws.close();
      ws.onclose = () => {
        setStatus('closed');                        // status
        if (!isMountedRef.current) return;           // guard
        const attempt = ++attemptsRef.current;       // backoff
        const delay = Math.min(30_000, 1000 * 2 ** attempt) + Math.random() * 1000;
        setTimeout(connect, delay);
      };
    };

    connect();
    return () => { isMountedRef.current = false; wsRef.current?.close(); };
  }, [url]);                                         // [url] only — handler is refed

  return { status };
}

assembledFull hook

The telemetry socket wrapper validates each frame and feeds the buffer; the ingest hook flushes; the baseline seeds. One useDashboard composes all three so a screen calls one hook.

// wrap the generic socket: validate frames, hand clean Telemetry to the buffer
function useTelemetrySocket(onFrame: (t: Telemetry) => void) {
  const onFrameRef = useRef(onFrame);
  onFrameRef.current = onFrame;

  useWebSocket<unknown>(wsUrl(), (raw) => {
    const parsed = TelemetrySchema.safeParse(raw);   // validate (don't trust `as T`)
    if (!parsed.success) return;                     // drop garbage frames
    onFrameRef.current(parsed.data);
  });
}

function useTelemetryIngest() {
  const bufferRef = useRef<Record<string, Telemetry>>({});

  useTelemetrySocket((frame) => {
    const prev = bufferRef.current[frame.vehicleId];
    if (prev && prev.ts >= frame.ts) return;
    bufferRef.current[frame.vehicleId] = frame;
  });

  useEffect(() => {
    const id = setInterval(() => {
      const batch = Object.values(bufferRef.current);
      if (batch.length === 0) return;
      bufferRef.current = {};
      useStore.getState().applyMany(batch);
    }, FLUSH_MS);
    return () => clearInterval(id);
  }, []);
}

// one hook a screen calls: seed + live ingest + the list of ids to render
function useDashboard() {
  useBaseline();        // REST seed → store
  useTelemetryIngest(); // WS deltas → buffer → store (5Hz)
  const ids = useStore((s) => Object.keys(s.byId));   // grid only re-renders when the SET of ids changes
  return { ids };
}

Object.keys(s.byId) only changes when an id is added/removed — so the grid layout is stable while values stream; the per-tile selectors carry the high-frequency updates.

Extensions

NeedApproach
Backpressure / bursty sourceThe buffer already coalesces to last-per-id per flush. If the producer outruns even that, cap the buffer and drop the oldest entries, or widen FLUSH_MS adaptively when batch size spikes.
Shed load under pressureDrop low-priority signals first: keep battery/speed at 5Hz, throttle non-critical fields to 1Hz (or skip them) so the important metrics never starve.
Many tiles at scaleSwap FlatList for FlashList (view recycling, not mount/unmount per row) so a grid of hundreds of tiles scrolls without per-row remount cost; per-id selectors keep updates isolated.
Rich per-tile visualsRender the gauge with Skia (or a Reanimated worklet) so the animation runs on the UI thread and a smooth needle does not add JS-thread render work per frame.
Avoid over-rendering on object identityUse a shallow equality selector (useStore(sel, shallow)) when a tile reads more than one field, so a patch that leaves the read fields unchanged does not re-render the tile.
