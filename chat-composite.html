Real-time Chat — Composite Build

Progressive, block-by-block: fetch history + optimistic send + live WebSocket + offline queue, converging on one cache.

Architecture & build order

The React Query cache ['messages', roomId] is the single source of truth. Three writers converge on it; the list is a pure render of it.

React Query cache  ['messages', roomId]    ← single source of truth
   ▲            ▲              ▲
   │            │              │
initial fetch   │          your sends
 (useQuery)     │      (optimistic + enqueue)
            live WS push
        (onMessage → setQueryData)

Build order — keep something runnable at every step: render → load → send → live → reconcile → harden. Each step below leaves a working app.

ATypes / data model

clientId is the dedup key (set on optimistic sends, echoed by the server). ts drives ordering. status is client-only — not from the server, so it lives outside the schema.

import { z } from 'zod';

const MessageSchema = z.object({
  id: z.string(),                    // server id (authoritative)
  clientId: z.string().optional(),   // client-generated → DEDUP key
  roomId: z.string(),
  senderId: z.string(),
  text: z.string(),
  ts: z.number(),                    // epoch ms → ORDERING
});
const MessagesSchema = z.array(MessageSchema);

type Message = z.infer<typeof MessageSchema> & {
  status?: 'pending' | 'sent' | 'failed';   // client-only optimistic marker
};

mechanismuseWebSocket (generic)

A reusable transport primitive — stable-ref handler so it reconnects only on [url], with jittered backoff. The chat layer wraps this; it knows nothing about chat.

type WsStatus = 'idle' | 'connecting' | 'open' | 'closed';

function useWebSocket<T>(url: string, onMessage: (msg: T) => void) {
  const [status, setStatus] = useState<WsStatus>('idle');
  const wsRef = useRef<WebSocket | null>(null);
  const attemptsRef = useRef(0);
  const isMountedRef = useRef(true);
  const onMessageRef = useRef(onMessage);
  onMessageRef.current = onMessage;                 // latest handler, every render — no reconnect

  useEffect(() => {
    isMountedRef.current = true;

    const connect = () => {
      if (!isMountedRef.current) return;
      setStatus('connecting');
      const ws = new WebSocket(url);
      wsRef.current = ws;

      ws.onopen = () => { attemptsRef.current = 0; setStatus('open'); };
      ws.onmessage = (e) => { try { onMessageRef.current(JSON.parse(e.data) as T); } catch {} };
      ws.onerror = () => ws.close();
      ws.onclose = () => {
        setStatus('closed');                        // status
        if (!isMountedRef.current) return;           // guard
        const attempt = ++attemptsRef.current;       // backoff
        const delay = Math.min(30_000, 1000 * 2 ** attempt) + Math.random() * 1000;
        setTimeout(connect, delay);
      };
    };

    connect();
    return () => { isMountedRef.current = false; wsRef.current?.close(); };
  }, [url]);                                         // [url] only — handler is refed

  return { status };
}

mechanismOffline outbox (enqueue / drain)

Queues writes while offline, persists them (MMKV), drains in order on reconnect. Each job carries an idempotency key so a retry can't double-apply. Generic — any feature enqueues any request.

import NetInfo from '@react-native-community/netinfo';
import { MMKV } from 'react-native-mmkv';

const storage = new MMKV();
const KEY = 'outbox';

type Job = { idempotencyKey: string; url: string; method: 'POST' | 'PUT' | 'PATCH' | 'DELETE'; body: unknown; attempts: number };

const load = (): Job[] => { const r = storage.getString(KEY); return r ? (JSON.parse(r) as Job[]) : []; };
const save = (jobs: Job[]) => storage.set(KEY, JSON.stringify(jobs));

let draining = false;

export function enqueue(job: Omit<Job, 'attempts'>) {
  const jobs = load();
  jobs.push({ ...job, attempts: 0 });
  save(jobs);
  void drain();
}

export async function drain(): Promise<void> {
  if (draining) return;
  const net = await NetInfo.fetch();
  if (!net.isConnected) return;
  draining = true;
  try {
    let jobs = load();
    while (jobs.length) {
      const job = jobs[0];
      try {
        const r = await fetch(job.url, {
          method: job.method,
          headers: { 'Content-Type': 'application/json', 'Idempotency-Key': job.idempotencyKey },
          body: JSON.stringify(job.body),
        });
        if (!r.ok) throw new Error(`HTTP ${r.status}`);
        jobs = jobs.slice(1);                        // success → drop head, keep draining
        save(jobs);
      } catch {
        jobs[0] = { ...job, attempts: job.attempts + 1 };
        save(jobs);
        break;                                       // failure → stop, retry next reconnect
      }
    }
  } finally {
    draining = false;
  }
}

NetInfo.addEventListener((s) => { if (s.isConnected) void drain(); });

CRead path — history + live

History is the useQuery in the skeleton. Live updates wrap the generic socket: build the url from roomId, validate each frame, merge into the same key. No useCallback needed — useWebSocket refs the handler.

function useChatSocket(roomId: string, key: readonly unknown[]) {
  const qc = useQueryClient();

  useWebSocket<unknown>(wsUrl(roomId), (raw) => {
    const parsed = MessageSchema.safeParse(raw);     // validate (don't trust `as T`)
    if (!parsed.success) return;                     // drop garbage frames
    const incoming = parsed.data;
    if (incoming.roomId !== roomId) return;          // guard (multiplexed socket)

    qc.setQueryData<Message[]>(key, (old = []) => mergeMessage(old, incoming));
  });
}

Changing roomId changes the url → useWebSocket reconnects to the new room and tears down the old socket, for free.

DSend — optimistic + enqueue

clientId does three jobs: optimistic identity, dedup key (matched by the WS echo), and idempotency key (reused by the outbox). Generated once.

const send = (text: string) => {
  const clientId = crypto.randomUUID();

  const optimistic: Message = {
    id: `temp-${clientId}`,                          // placeholder until server id arrives
    clientId, roomId, senderId: currentUserId, text,
    ts: Date.now(), status: 'pending',
  };

  qc.setQueryData<Message[]>(key, (old = []) => [...old, optimistic]);   // instant bubble

  enqueue({
    idempotencyKey: clientId,                        // retry-safe
    url: `${API_URL}/rooms/${roomId}/messages`,
    method: 'POST',
    body: { clientId, text },                        // server echoes clientId on the WS broadcast
  });
};

No onSuccess: the WebSocket echo is the reconciliation channel — the read path closes the write path's loop. Online or after a reconnect, the echo flips the bubble pending → sent.

EReconcile — dedup + ordering

Every socket frame runs through this: skip duplicates by server id, reconcile my own echo by clientId (swap temp → server, mark sent), else append.

function mergeMessage(list: Message[], incoming: Message): Message[] {
  if (list.some((m) => m.id === incoming.id)) return list;          // WS redelivery

  const i = list.findIndex((m) => m.clientId && m.clientId === incoming.clientId);
  if (i !== -1) {                                                   // echo of MY optimistic send
    const copy = list.slice();
    copy[i] = { ...incoming, status: 'sent' };                      // temp → server version
    return copy;
  }
  return [...list, incoming];                                       // new message from someone else
}

Ordering: sort by ts on read via select, then an inverted FlatList. Keep the bubble's key on clientId (when present) so it stays stable through the temp→server swap and doesn't flicker.

assembledFull useChat

function useChat(roomId: string) {
  const qc = useQueryClient();
  const key = ['messages', roomId] as const;

  const { data: messages = [], status } = useQuery({
    queryKey: key,
    queryFn: () => getMessages(roomId),
    select: (msgs) => [...msgs].sort((a, b) => b.ts - a.ts),   // newest first (for inverted list)
  });

  useChatSocket(roomId, key);

  const send = (text: string) => {
    const clientId = crypto.randomUUID();
    const optimistic: Message = {
      id: `temp-${clientId}`, clientId, roomId,
      senderId: currentUserId, text, ts: Date.now(), status: 'pending',
    };
    qc.setQueryData<Message[]>(key, (old = []) => [...old, optimistic]);
    enqueue({
      idempotencyKey: clientId,
      url: `${API_URL}/rooms/${roomId}/messages`,
      method: 'POST',
      body: { clientId, text },
    });
  };

  return { messages, send, status };
}

function ChatScreen({ roomId }: { roomId: string }) {
  const { messages, send, status } = useChat(roomId);
  const [draft, setDraft] = useState('');

  if (status === 'pending') return <ActivityIndicator />;
  if (status === 'error')   return <Text>Couldn't load messages</Text>;

  const onSend = () => {
    const text = draft.trim();
    if (!text) return;
    send(text);
    setDraft('');
  };

  return (
    <SafeAreaView style={{ flex: 1 }} edges={['top']}>
      <KeyboardAvoidingView
        style={{ flex: 1 }}
        behavior={Platform.OS === 'ios' ? 'padding' : 'height'}
        keyboardVerticalOffset={Platform.OS === 'ios' ? 64 : 0}
      >
        <FlatList
          data={messages}                              // already newest-first via select
          inverted
          keyExtractor={(m) => m.clientId ?? m.id}      // stable through temp→server swap
          renderItem={({ item }) => (
            <MessageBubble message={item} mine={item.senderId === currentUserId} />
          )}
        />
        <View style={styles.composer}>
          <TextInput value={draft} onChangeText={setDraft} placeholder="Message…" style={styles.input} multiline />
          <Pressable onPress={onSend} disabled={!draft.trim()} style={styles.sendBtn}><Text>Send</Text></Pressable>
        </View>
      </KeyboardAvoidingView>
    </SafeAreaView>
  );
}

Extensions

NeedApproach
Survive restart / read offlineSQLite as source of truth: read local → fetch delta since last ts (?since=) → WS for live. The delta also closes the gap where the socket missed pushes while closed. (Or persistQueryClient for a lighter "instant paint.")
Long historyuseInfiniteQuery with a cursor; onEndReached on the (inverted) list to page older messages.
Many rooms at scaleOne multiplexed socket lifted to app level (don't reconnect per room); the roomId guard becomes routing into the right cache key.
Permanent send failureOutbox gives up after N attempts → a hook sets status: 'failed' on that clientId → "tap to retry" re-enqueues.
Single source of truthPick the RQ cache or a persisted store for "messages" — never render from both, or items double.
